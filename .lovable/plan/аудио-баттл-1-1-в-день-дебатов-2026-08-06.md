# Аудио-баттл 1×1 в день дебатов

Перестраиваем дуэль: тема больше не вводится игроком, вход только в день баттлов, реплики — голосом в живой комнате.

## Как это будет выглядеть для игрока

1. На главной в режиме Game Day появляется кнопка «Войти в баттл». Вне окна события кнопки нет — вместо неё отсчёт до ближайшего дня дебатов.
2. Игрок нажимает — попадает в комнату по теме недели (тему задаёт админ, она уже раскрыта в Game Day).
3. Если кто-то уже ждёт — пара сходится. Иначе экран ожидания соперника.
4. Кубик назначает стороны: «За» и «Против». Игрок сторону не выбирает.
5. **2 минуты подготовки**: таймер, тема, своя сторона, блокнот для тезисов (локальный, не видит соперник). Микрофон выключен.
6. **Раунд, 6 ходов по очереди**, микрофон открыт только у того, чей ход:
   - Конструктив «За» — 90 сек
   - Конструктив «Против» — 90 сек
   - Опровержение «За» — 60 сек
   - Опровержение «Против» — 60 сек
   - Финал «За» — 45 сек
   - Финал «Против» — 45 сек
   Итого около 7 минут. На экране: кто говорит, таймер хода, порядок ходов.
7. Речь каждого хода расшифровывается в текст.
8. AI-судья читает всю стенограмму, объявляет победителя, даёт оценки по 5 критериям и советы обоим. Elo обновляется.
9. Экран результата: вердикт, стенограмма по ходам, запись доступна для прослушивания.

## Что убираем

- Поле ввода темы и кнопку «Кубик темы» в дуэли.
- Возможность стартовать дуэль в любой день.
- Текстовый ввод реплик как основной режим (останется как запасной, если микрофон недоступен).

## Техническая часть

**Аудио.** Живая комната на LiveKit: сервер выдаёт токен участнику, права на публикацию звука включаются только на его ход. Для этого нужен аккаунт LiveKit Cloud — понадобятся ключ, секрет и URL проекта; запрошу их отдельно, когда дойдём до этого шага.

**Расшифровка.** Аудио каждого хода записывается и отправляется на распознавание речи (Lovable AI), текст сохраняется в `duel_turns` — так AI-судья и Elo продолжают работать на текущей логике.

**База.**
- `duels`: добавить `week_id` (тема берётся из недели), `phase` (`waiting` / `prep` / `live` / `judging` / `done`), `prep_ends_at`, `room_name`, `recording_url`. Убрать смысл ручного `motion` — заполняется темой недели.
- `duel_turns`: добавить `audio_path`, `duration_sec`; `text` становится расшифровкой.
- Новый bucket для записей ходов.
- Очередь ожидания привязана к неделе, а не к произвольной теме.

**Доступность по календарю.** Серверная проверка: старт дуэли разрешён только между `event_at` и `event_ends_at` текущей недели, и только если тема раскрыта. Клиентская кнопка на главной показывается по тем же данным.

**Тайминги** выносим в `duel-config.ts` (массив длительностей по ходам + 120 сек подготовки), чтобы админ-панель позже могла их менять.

## Порядок работы

1. Миграция базы + bucket.
2. Логика входа по календарю, очередь по теме недели, кубик сторон, фаза подготовки — на текстовых ходах (проверяемо сразу).
3. Подключение LiveKit: комната, токены, микрофон по очереди.
4. Расшифровка речи и передача стенограммы судье.
5. Кнопка на главной в Game Day, удаление старого входа.
